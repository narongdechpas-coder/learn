Solution architecture

ระบบเชื่อมกันอย่างไร

CRM ทำหน้าที่ทำงานกับเคส (Ticket, SLA, Routing) ส่วน CDP เป็นศูนย์รวมตัวตนลูกค้า (Identity) และคำแนะนำ (NBA) โดยดึงข้อมูลกรมธรรม์และเคลมจาก Core System

Real-time API (< 300 ms) Event stream (เขียนกลับเข้า CDP) Batch / Sync รายวัน

ลำดับข้อมูลเมื่อมีสายเข้า

  1. สาย / แชทเข้าCTI ได้เบอร์โทร (ANI), LINE ได้ UID, Facebook ได้ PSID แล้วส่งเข้าคิวตาม IVR หรือ Keyword
  2. Identity ResolutionCRM ส่ง Identifier ให้ CDP จับคู่แบบ Deterministic (เบอร์, LINE UID) หรือ Probabilistic (Cookie) ถ้าเบอร์ไม่ตรงหรือซ่อนเบอร์ Agent ยืนยันด้วยเลขบัตร ปชช. + วันเกิด แล้ว Map กับ Customer ID
  3. Screen PopCDP คืน Profile 360, กรมธรรม์, เคลม, Journey, Sentiment และ NBA แล้วแสดงเป็น Pop-up ก่อน Agent กดรับ
  4. เปิด Ticket & AssignAgent เลือกหมวด CRM คำนวณ SLA และส่งต่อส่วนงานตาม Routing rule ระบบ AI ช่วยสรุปบทสนทนา
  5. Wrap-up & เขียนกลับเข้า CDPบันทึก Disposition, Consent (PDPA), ผล NBA แล้วส่ง Event อัปเดต Segment และสั่ง Journey ต่อ
  6. ส่วนงานรับเรื่อง & ปิด TicketUnderwriting, Claims หรือทีมจัดส่งทำงานต่อใน CRM ขอเอกสารเพิ่มได้ (SLA หยุดนับ) บันทึกผล ปิด Ticket แจ้งลูกค้าและ Agent แล้วส่ง CSAT
