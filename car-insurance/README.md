# ระบบประกันรถยนต์ออนไลน์ (เดโม)

เช็คเบี้ยประกันรถยนต์ → ชำระเงิน → รับกรมธรรม์แบบ PDF

> ⚠️ ระบบนี้เป็นเดโมเพื่อการเรียนรู้ อัตราเบี้ยเป็นตัวอย่าง และการชำระเงินเป็นแบบจำลอง (mock) ไม่มีการตัดเงินจริง

## เริ่มใช้งาน

```bash
cd car-insurance
npm install
npm start          # เปิด http://localhost:3000
npm test           # รันชุดทดสอบ
```

### ไม่สะดวกติดตั้ง Node.js? ใช้เวอร์ชันเบราว์เซอร์

`npm run build:demo` จะได้ไฟล์ `dist/demo.html` ไฟล์เดียว ที่รันทุกอย่างในเบราว์เซอร์
(ใช้โค้ดคำนวณเบี้ย/ชำระเงิน/สร้าง PDF ชุดเดียวกับเซิร์ฟเวอร์ แต่ข้อมูลอยู่ในหน่วยความจำ ปิดหน้าแล้วหาย)
นำไฟล์นี้ไปเปิดในเบราว์เซอร์หรือวางบนเว็บโฮสติ้งแบบ static ได้เลย

ตัวแปรแวดล้อม: `PORT` (ค่าเริ่มต้น 3000), `DATA_FILE` (ค่าเริ่มต้น `data/db.json`),
`ENABLE_MOCK_GATEWAY=false` เพื่อปิด endpoint ของ gateway จำลอง

## ขั้นตอนการใช้งาน

1. **ข้อมูลรถ** — ยี่ห้อ รุ่น ปี ราคารถ ประเภทรถ พื้นที่ใช้รถ อายุผู้ขับขี่ ซ่อมห้าง/อู่ ค่าเสียหายส่วนแรก
2. **เลือกแผน** — ชั้น 1 / 2+ / 3+ / 3 พร้อมราคารวมภาษีอากร และเลือกซื้อ พ.ร.บ. เพิ่มได้
3. **ข้อมูลผู้เอาประกัน** — ชื่อ เลขบัตรประชาชน (ตรวจ checksum) ติดต่อ ทะเบียน/เลขตัวถัง วันเริ่มคุ้มครอง
4. **ชำระเงิน** — บัตรเครดิต/เดบิต หรือ Thai QR (พร้อมเพย์)
   - บัตรทดสอบ `4242 4242 4242 4242` = สำเร็จ, `4000 0000 0000 0002` = ถูกปฏิเสธ (วันหมดอายุอนาคต, CVV 3 หลักใดก็ได้)
   - พร้อมเพย์: สร้าง QR แล้วกดปุ่ม "(ทดสอบ) จำลองว่าสแกนจ่ายแล้ว"
5. **รับกรมธรรม์** — เปิดดู / ดาวน์โหลด PDF ภาษาไทย

## โครงสร้าง

```
src/
  premium.js     สูตรคำนวณเบี้ย ชั้น 1/2+/3+/3, พ.ร.บ., อากรแสตมป์, VAT 7%
  validation.js  ตรวจเลขบัตรประชาชน, Luhn, ข้อมูลผู้เอาประกัน
  payment.js     payment gateway จำลอง (tokenize บัตร, charge, Thai QR EMVCo + CRC16)
  policyPdf.js   สร้าง PDF กรมธรรม์ด้วย pdfkit + ฟอนต์ Sarabun
  store.js       ที่เก็บข้อมูล (JSON file)
  service.js     ตรรกะหลัก (เช็คเบี้ย/สั่งซื้อ/ชำระเงิน) ไม่ผูกกับ Express
  server.js      Express API (ห่อ service.js)
demo/            เวอร์ชันเบราว์เซอร์ล้วน (ดัก fetch แล้วเรียก service.js โดยตรง)
public/          หน้าเว็บ (HTML/CSS/JS ล้วน)
fonts/           ฟอนต์ Sarabun (SIL OFL 1.1)
test/            unit test + ทดสอบ flow ครบวงจรผ่าน API
```

## API

| Method | Path | คำอธิบาย |
|---|---|---|
| GET | `/api/options` | ตัวเลือกในฟอร์ม |
| POST | `/api/quotes` | คำนวณเบี้ย → `quoteId`, แผน, ราคา (หมดอายุใน 30 นาที) |
| POST | `/api/orders` | สร้างคำสั่งซื้อจาก quote → `id`, `accessToken`, `amount` |
| GET | `/api/orders/:id` | สถานะคำสั่งซื้อ (header `x-order-token`) |
| POST | `/api/orders/:id/pay` | `{ method: "card", cardToken }` หรือ `{ method: "promptpay" }` |
| GET | `/api/orders/:id/policy.pdf?token=…` | ดาวน์โหลดกรมธรรม์ (เฉพาะที่ชำระแล้ว) |

## หลักความปลอดภัยที่ใช้

- **ราคาคิดฝั่งเซิร์ฟเวอร์เสมอ** — client ส่งแค่ `quoteId` + `planCode` ไม่ส่งราคา
- **เลขบัตรไม่ผ่านเซิร์ฟเวอร์เรา** — เบราว์เซอร์ tokenize กับ gateway ก่อน แล้วส่งแค่ token (token ใช้ได้ครั้งเดียว)
- **ออกกรมธรรม์แบบ idempotent** — ตรวจยอดเงินตรงกับคำสั่งซื้อ และไม่ออกซ้ำ
- **ป้องกันการเดา URL** — ดูคำสั่งซื้อ/PDF ต้องมี access token แบบสุ่ม เทียบด้วย `timingSafeEqual`

## ก่อนนำไปใช้จริง

- เปลี่ยน `src/payment.js` เป็น gateway จริง (Omise, 2C2P, GB Prime Pay, KBank/SCB API) และรับผลผ่าน webhook ที่ตรวจลายเซ็น
- เปลี่ยน `src/store.js` เป็นฐานข้อมูลจริง และเพิ่มระบบสมาชิก/ล็อกอิน
- ใช้อัตราเบี้ยจริงจากบริษัทประกัน/พิกัดอัตรา คปภ. และเชื่อมระบบออกกรมธรรม์ของบริษัทประกัน
- ใบอนุญาตนายหน้า/ตัวแทนประกันวินาศภัยจาก คปภ., นโยบาย PDPA, ส่งกรมธรรม์ทางอีเมล, ลายมือชื่ออิเล็กทรอนิกส์
